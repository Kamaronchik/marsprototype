# Бэкап и восстановление базы

Вся информация школы лежит в Supabase (Postgres): ученики, оценки, платежи, журнал действий.
Файлы резюме лежат в Supabase Storage (приватный bucket `resumes`) отдельно от базы.
Бэкап нужен на случай, если кто-то удалил данные по ошибке или проект Supabase сломался.

## Что делать регулярно

| Как часто | Что | Зачем |
|-----------|-----|-------|
| Раз в неделю | Сделать дамп базы (ниже) | Свежая копия на своём компьютере |
| Перед каждой новой миграцией | Сделать дамп | Можно откатиться, если миграция что-то сломала |
| Раз в месяц | Проверить, что дамп открывается и восстанавливается | Бэкап, который ни разу не проверяли, может не работать |

Автоматические бэкапы Supabase есть только на платном тарифе (Pro). На бесплатном тарифе их нет,
поэтому ручной дамп обязателен.

## Сделать бэкап

1. Установить PostgreSQL client tools (нужен `pg_dump`): https://www.postgresql.org/download/
2. В Supabase: **Project settings -> Database -> Connection string -> URI**.
   Взять строку для **Session pooler** и подставить пароль базы.
3. Записать строку в переменную (она содержит пароль, никому не показывать и не коммитить):

```bash
export DATABASE_URL="postgresql://postgres.xxxx:ПАРОЛЬ@aws-0-xx.pooler.supabase.com:5432/postgres"
```

4. Сделать дамп. Файлы кладём в папку вне проекта (например `~/mars-backups`), не в git:

```bash
mkdir -p ~/mars-backups
pg_dump "$DATABASE_URL" --no-owner --no-privileges --schema=public \
  --format=custom --file=~/mars-backups/mars-$(date +%Y-%m-%d).dump
```

5. Если нужен читаемый текст (SQL), то же самое с `--format=plain --file=...sql`.

Резюме (Storage): в Supabase **Storage -> resumes** можно выделить файлы и скачать. Резюме не критичны,
но их тоже стоит скачивать раз в месяц.

## Восстановить

Восстанавливать лучше в **новый пустой проект** Supabase, а не поверх рабочего.

1. Создать новый проект на supabase.com.
2. Развернуть структуру: выполнить миграции `supabase/migrations/001..` по порядку
   (см. `supabase/migrations/README.md`). Этот шаг создаёт таблицы, функции и защиту RLS.
3. Загрузить данные из дампа (только данные, структура уже есть):

```bash
export NEW_DATABASE_URL="postgresql://postgres.yyyy:ПАРОЛЬ@aws-0-xx.pooler.supabase.com:5432/postgres"
pg_restore --no-owner --no-privileges --data-only --disable-triggers \
  --dbname="$NEW_DATABASE_URL" ~/mars-backups/mars-2026-11-14.dump
```

4. Вписать в `.env` (и в Vercel) новые `SUPABASE_URL` и `SUPABASE_SECRET_KEY` от нового проекта.
5. Заново поставить Telegram webhook: `npm run bot-webhook -- https://ваш-сайт.vercel.app`.
6. Проверить: войти админом, открыть список учеников, платежи и журнал действий.

## Если по ошибке удалили несколько строк

Не нужно восстанавливать всю базу. Поднимите дамп во временный проект (шаги выше), найдите нужные
строки в SQL Editor и перенесите их `INSERT`-ом в рабочую базу.

## Правила безопасности

- Дамп содержит хэши паролей и личные данные. Хранить только у себя, не отправлять в чаты и не класть в git.
- Строка подключения и ключи живут только в `.env` и в настройках Vercel.
- Если дамп или ключ попал не туда: сменить пароль базы (Project settings -> Database) и выпустить новый `service_role` ключ.
