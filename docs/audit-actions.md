# Аудит каждого действия

Третья часть аудита. Первая ([audit-catalog.md](audit-catalog.md)) — правила школы, вторая
([audit-conduct.md](audit-conduct.md)) — поведение людей. Эта — **каждое маленькое действие**:
отметил ученика, поставил оценку, выдал коины, вошёл, купил, удалил.

Для каждого действия три вопроса:

1. **Что записать** — какие поля попадают в журнал.
2. **Что запретить сразу** — сервер не даёт сделать (жёсткая проверка, ответ 403/409).
3. **Что заметить потом** — действие разрешено, но выглядит странно; правило создаёт сигнал для аудитора.

Сигнал — не нарушение. Сигнал = «посмотри сюда». Нарушение ставит человек после проверки.

---

## 0. Что уже пишется в журнал и чего нет

Проверено по коду (`logAction` в `server/`), 2026-11-17.

**Пишется:** вход и неудачный вход, отметка и изменение посещаемости, оценки (добавить, удалить), проверка ДЗ,
урок, группы (создать, изменить, ученики, учитель, предмет, архив), расписание, предметы, пользователи (создать,
роль, статус, пароль, удалить), пополнение баланса, платежи, зарплаты, расходы, товары, переводы, заявки кандидатов,
нарушения, штрафы, правила. Плюс триггеры базы на `attendance` и `grades`.

**Не пишется в `audit_log` (дыры):**

| Действие | Маршрут | Почему важно |
|---|---|---|
| Создать / убрать ДЗ | `POST /homework`, `DELETE /homework/:id` | можно задним числом «задать» ДЗ перед проверкой завуча |
| Ученик сдал ДЗ | `POST /homework/:id/submit` | спор «я сдавал» — нечем доказать |
| Выдать коины ученику | `POST /wallet/award` | любимчики, перевод коинов «своим» |
| Коины учителю, пополнение пула | `POST /wallet/grant`, `/pool-topup` | админ может раздать коины без следа в журнале действий |
| Покупка, подтверждение, отмена заказа | `/shop/purchases`, `/orders/:id/cancel` | кражи через чужой аккаунт |
| Статус заказа (выдан / отменён) | `orderController` | «выдал» товар, которого ученик не получал |
| Оценка урока учеником | `POST /ratings` | накрутка оценок урока |
| Битвы: ответы | `/battle/:id/answer` | читерство, фарм коинов |
| Выход, подтверждение устройства, удаление устройства | `/auth/logout`, `/verify-device`, `/devices/:id` | расследование взлома |
| Telegram: привязать / отвязать | `/telegram/link` | чужой Telegram на аккаунте ученика |
| Просмотр личных данных (список учеников с телефонами, отчёты) | GET-маршруты | утечки — это чтение, а не запись |
| Экспорт в Excel, печать | фронт | выгрузка всей базы одним кликом |

Первый шаг любой работы с аудитом — закрыть эти дыры: без записи нечего проверять.

## 1. Отметка ученика (посещаемость)

Самое частое действие в школе. 20 уроков в день × 12 учеников = 240 отметок в день. Здесь больше всего ошибок и обмана.

### 1.1 Что записать

`кто отметил`, `ученик`, `группа`, `дата урока`, `статус` (пришёл / опоздал / нет), `было → стало`,
`время отметки` (часы базы), `IP`, `устройство`, `минут от начала урока`, `сколько секунд на всю группу`,
`причина изменения` (если меняли), `было ли списание денег`.

### 1.2 Что запретить сразу

| Проверка | Почему |
|---|---|
| Отмечать можно только свою группу | уже есть |
| Нельзя отметить урок, которого нет в расписании на эту дату | иначе можно списать деньги за несуществующий урок |
| Нельзя отметить раньше чем за 10 минут до начала | отметка «заранее» = учитель не смотрит, кто пришёл |
| Нельзя отметить замороженного или ушедшего ученика | уже частично есть |
| Нельзя отметить ученика, добавленного в группу позже даты урока | задним числом в чужой урок |
| Изменение старше 48 часов — только с причиной и через завуча | история не должна плавать |
| Нельзя поставить «пришёл» в двух группах в одно и то же время | ученик не может быть в двух кабинетах |
| «Нет» → «пришёл» после закрытия месяца — запрещено | месяц уже посчитан в зарплатах и отчётах |

### 1.3 Что заметить потом (сигналы)

| Код | Сигнал | Почему подозрительно |
|---|---|---|
| `MARK_TOO_FAST` | Вся группа отмечена меньше чем за 5 секунд | учитель нажал «все пришли», не глядя |
| `MARK_FROM_OUTSIDE` | Отметка с IP не школы | учитель отмечает из дома = урока могло не быть |
| `MARK_AFTER_END` | Отметка после конца урока | забыл и вспоминал по памяти — ошибки |
| `MARK_ALWAYS_ALL` | 100% присутствия 4 недели подряд в группе больше 8 человек | так почти не бывает |
| `MARK_NEVER_LATE` | В группе за месяц ни одного «опоздал» | статус «опоздал» не используется, отметки формальные |
| `MARK_FLIP` | Один ученик много раз «нет» ↔ «пришёл» | торг с учеником или родителем |
| `MARK_ABSENT_TO_PRESENT` | После урока «нет» поменяли на «пришёл» | самая частая подделка: ради отчёта или списания |
| `MARK_PRESENT_TO_ABSENT` | После списания «пришёл» поменяли на «нет» | возврат денег «своему» ученику |
| `PRESENT_BUT_ONLINE_ELSEWHERE` | Ученик «пришёл», а в это время играл в битву с телефона с домашнего IP | физически его не было |
| `PRESENT_BUT_PARENT_NO` | Родитель в боте ответил «ребёнок не был» | прямое противоречие |
| `ABSENT_BUT_SUBMITTED_IN_CLASS` | «Нет», а ДЗ сдано из школьной сети во время урока | ученик был, учитель ошибся |
| `MARKED_BY_OTHER` | Урок отметил не учитель группы (админ, другой учитель) без замены в расписании | кто на самом деле вёл урок? |
| `SAME_DEVICE_TWO_TEACHERS` | Два учителя отмечают с одного устройства | один отмечает за другого |

### 1.4 Креативные проверки

- **Подтверждение родителем.** Отметка «пришёл» → родителю в Telegram: «Али отмечен на уроке Python в 15:04».
  Кнопки «Да» / «Его не было». Одна кнопка закрывает 80% подделок, а родитель видит, что школа следит.
- **Код урока.** В начале урока на экране проектора 4 цифры, меняются каждые 30 секунд. Ученик вводит их у себя.
  Отметка учителя без кода ученика = сигнал. Не заменяет учителя, а проверяет его.
- **Случайный вопрос ученику.** Раз в неделю бот спрашивает случайного ученика: «Ты был на уроке в среду?».
  Ответ сравнивается с журналом.
- **Счётчик стульев.** Админ при обходе вводит «в 204 сидит 9 человек». Журнал говорит 12 — сигнал.

## 2. Оценки

### Что записать

`кто`, `кому`, `за что` (урок, ДЗ, экзамен), `оценка было → стало`, `комментарий`, `время от сдачи работы до оценки`.

### Запретить сразу

- Оценка только ученику своей группы и только за дату, когда он был в группе.
- Удаление оценки — только с причиной. Удалённая оценка не исчезает, а помечается.
- Оценку за экзамен меняет только завуч.

### Сигналы

| Код | Сигнал |
|---|---|
| `GRADE_INFLATION_BEFORE_REPORT` | Перед отчётом родителям или проверкой завуча оценки группы резко выросли |
| `GRADE_SAME_FOR_ALL` | Всей группе одна и та же оценка за работу |
| `GRADE_NO_WORK` | Оценка за ДЗ, которое ученик не сдавал |
| `GRADE_INSTANT` | Оценка через 10 секунд после сдачи большой работы — не проверял |
| `GRADE_DELETE_LOW` | Удаляются только плохие оценки одному ученику |
| `GRADE_TEACHER_GAP` | У одного учителя средняя 4.8, у других по тому же предмету 3.9 |
| `GRADE_VS_BATTLE` | Отличник по журналу проваливает все битвы по этой теме — оценки не отражают знания |
| `GRADE_WEEKEND_EDIT` | Оценки меняются в выходной ночью |
| `GRADE_AFTER_COMPLAINT` | Родитель пожаловался → оценки ребёнка выросли на следующий день |

## 3. Урок и домашнее задание

| Действие | Что заметить |
|---|---|
| Записал тему урока | `TOPIC_COPY`: тема та же, что неделю назад; `TOPIC_GENERIC`: «практика», «повторение» 5 раз подряд; `TOPIC_OFF_PLAN`: тема не из учебного плана |
| Задал ДЗ | `HW_BACKDATED`: ДЗ создано после срока сдачи; `HW_NO_DESCRIPTION`: пустое описание; `HW_DEADLINE_TOO_SHORT`: срок меньше 24 ч |
| Убрал ДЗ | `HW_ARCHIVED_WITH_ANSWERS`: убрал ДЗ, на которое уже ответили (ученики теряют работу) |
| Ученик сдал | `HW_SUBMIT_DEADLINE_RUSH`: вся группа сдаёт за 2 минуты до срока одинаковое; `HW_SUBMIT_FROM_ONE_IP`: разные ученики с одного IP вне школы (один делает за всех) |
| Проверил ДЗ | `HW_NO_FEEDBACK`: оценка без единого слова комментария 20 раз подряд |
| Урок без активности | `LESSON_SILENT`: урок «прошёл», но ни один ученик не открыл платформу за 90 минут |

## 4. Коины, магазин, битвы

### Коины

| Код | Сигнал / запрет |
|---|---|
| запрет | Выдать коины можно только ученику своей группы и только из своего пула (уже есть) |
| запрет | Не больше N коинов одному ученику в день |
| `COIN_ONE_STUDENT` | Больше 40% пула учителя ушло одному ученику за месяц |
| `COIN_RELATIVE` | Учитель и ученик с одной фамилией / один номер родителя в анкете |
| `COIN_ROUND_DUMP` | Учитель в последний день месяца раздал весь пул сразу (пул «сгорает») |
| `COIN_NO_REASON` | Выдача без причины («за что») |
| `COIN_ADMIN_GRANT_SELF` | Админ пополнил пул учителю, который потом выдал коины ребёнку админа |
| `COIN_INFLATION` | Коинов в обороте стало на 50% больше, а товаров столько же — магазин опустеет |

### Магазин

| Код | Сигнал |
|---|---|
| `SHOP_NEW_DEVICE_BUY` | Покупка на всю сумму сразу после входа с нового устройства — кража аккаунта |
| `SHOP_ORDER_NOT_GIVEN` | Заказ «выдан», но ученик через бота говорит, что не получил |
| `SHOP_GIVEN_BY_SAME` | Один админ сам меняет цены и сам выдаёт заказы |
| `SHOP_PRICE_DROP_BUY` | Цену снизили → сразу купил один ученик → цену вернули |
| `SHOP_STOCK_MISMATCH` | Остаток в системе не совпадает с полкой (ежемесячная инвентаризация) |
| `SHOP_CANCEL_LOOP` | Покупка и отмена много раз (поиск ошибки в списании) |

### Битвы

| Код | Сигнал |
|---|---|
| `BATTLE_TOO_FAST` | Ответ быстрее 1 секунды на вопрос из 30 слов — бот или подсказка |
| `BATTLE_SAME_PAIR` | Два ученика играют друг с другом 30 раз в день, один всегда сдаётся — фарм коинов |
| `BATTLE_IN_LESSON` | Ученик играет в битвы во время своего урока |
| `BATTLE_ALL_CORRECT` | 100% правильных во всех битвах при средних оценках — вопросы утекли |

## 5. Деньги (каждое действие)

| Действие | Что записать | Запретить | Сигнал |
|---|---|---|---|
| Пополнить баланс | сумма, способ, номер чека | без чека, сумма ≤ 0 | `TOPUP_ROUND_NIGHT`: круглая сумма ночью; `TOPUP_SELF_FAMILY`: админ пополняет ребёнку из своей семьи |
| Принять платёж | сумма, ученик, месяц, касса | дважды за один месяц без пометки | `PAY_DUPLICATE`: два одинаковых платежа за 5 минут; `PAY_SPLIT`: платёж разбит на части под лимит одобрения |
| Скидка | процент, причина, кто одобрил | без причины | `DISCOUNT_SAME_ADMIN`: все скидки от одного админа одним и тем же семьям |
| Зарплата | учитель, месяц, уроки, сумма | больше, чем уроков × ставка, без комментария | `SALARY_NO_LESSONS`: зарплата учителю, у которого нет уроков в месяце |
| Расход | категория, сумма, чек | без фото чека выше N | `EXPENSE_JUST_UNDER`: много расходов чуть ниже порога одобрения; `EXPENSE_BENFORD`: первые цифры сумм распределены неестественно (выдуманные числа); `EXPENSE_SAME_VENDOR_NEW`: новый поставщик и сразу большие суммы |
| Изменить / удалить расход | было → стало, причина | удалить после закрытия месяца | `EXPENSE_EDIT_AFTER_REPORT`: правка после отчёта CEO |
| Напомнить должникам | кому ушло | чаще раза в 3 дня одному | `REMIND_NONE_DEBTOR`: ушло тому, кто уже заплатил |

## 6. Пользователи и права

| Действие | Сигнал |
|---|---|
| Создать пользователя | `USER_NO_GROUP`: ученик создан, но не добавлен ни в одну группу 7 дней (мёртвая душа или забыли); `USER_DUPLICATE`: тот же телефон / имя у двух аккаунтов |
| Сменить роль | `ROLE_UP_SELF_CIRCLE`: роль повышена человеку, который только что создан; любое повышение → CEO всегда |
| Сменить пароль другому | `PASSWORD_RESET_THEN_LOGIN`: админ сбросил пароль и сразу вошёл в этот аккаунт сам (тот же IP) |
| Заморозить / разморозить | `FREEZE_BEFORE_CHARGE`: заморозили утром, разморозили вечером — день без списания |
| Удалить пользователя | `DELETE_WITH_DEBT`: удалён ученик с долгом (долг «исчез») |
| Вход | `LOGIN_TWO_CITIES`: вход из двух мест за 10 минут; `LOGIN_AFTER_FIRED`: попытка входа после увольнения; `LOGIN_SHARED_STAFF`: один аккаунт сотрудника с 3 устройств |
| Новое устройство | `DEVICE_CODE_MANY`: много запросов кода 2FA подряд — подбор |
| Telegram привязка | `TG_RELINK`: аккаунт ученика привязан к новому Telegram, старый отвязан тем же днём |

## 7. Группы и расписание

| Действие | Сигнал |
|---|---|
| Перевести ученика | `TRANSFER_TO_EASY`: ученика переводят к учителю, у которого выше оценки, перед экзаменом |
| Убрать ученика из группы | `REMOVE_NO_EXIT_REASON`: без причины ухода |
| Сменить учителя группы | `TEACHER_SWAP_OFTEN`: группа сменила 3 учителей за 2 месяца — ученики уйдут |
| Изменить расписание | `SCHEDULE_CHANGE_SAME_DAY`: изменили время урока в день урока — родители не знают; `SCHEDULE_HIDES_NO_SHOW`: урок убрали из расписания задним числом, когда учитель не пришёл |
| Архив группы | `ARCHIVE_WITH_BALANCE`: в архив ушла группа, у учеников остались деньги на балансе |

## 8. Чтение данных (не только запись)

Утечки происходят, когда смотрят, а не когда меняют. Записывать стоит не всё, а чувствительное.

| Что смотрят | Сигнал |
|---|---|
| Список учеников с телефонами родителей | `PII_BULK_VIEW`: учитель пролистал всех учеников школы, а не своих |
| Резюме кандидатов | уже пишется (`application.view_resume`) |
| Зарплаты | `SALARY_VIEW_UNUSUAL`: финансист открыл зарплаты 30 раз за день |
| Жалобы (из второй части) | каждое открытие в журнал |
| Экспорт Excel | `EXPORT_BEFORE_LEAVE`: сотрудник выгрузил базу за неделю до увольнения |

## 9. Невозможные факты (сверка разных данных)

Самые сильные проверки — когда два источника противоречат друг другу. Ни один человек не врёт сразу во всех местах.

| Противоречие | Что значит |
|---|---|
| Учитель отметил два урока в одно время в разных кабинетах | один урок не был проведён |
| Учитель «на уроке», а его аккаунт в это время меняет оценки с домашнего IP | его нет в школе |
| Урок отмечен, а кабинет по расписанию закрыт / ремонт | урока не было |
| Ученик «пришёл» в день, когда школа была закрыта (праздник) | ошибка или подделка |
| Списание за урок есть, отметки нет (или наоборот) | ошибка денег |
| В кабинете 10 компьютеров, отмечено 14 «пришедших» | места нет |
| Учитель получил зарплату за 20 уроков, в журнале 16 | переплата |
| Чек-лист кабинета сдан, а последний урок в кабинете отменён | чек-лист подделан |
| Средняя оценка урока 5.0, а половина группы ушла за месяц | оценки урока накручены |
| Родитель платит наличными каждый месяц, а ребёнок не ходит 2 месяца | деньги идут мимо или ошибка |

## 10. Аудит самого аудита

Кто следит за следящими:

| Код | Сигнал |
|---|---|
| `RULE_DISABLED` | Правило выключили — CEO всегда, с причиной |
| `RULE_SOFTENED` | Срок эскалации увеличили или штраф уменьшили сразу после нарушения конкретного человека |
| `VIOLATION_DISMISSED_FRIEND` | Завуч закрывает нарушения одного учителя как «ложные» чаще, чем у других |
| `FINE_CANCEL_RATE` | CEO отменяет больше 50% штрафов — правило настроено плохо, а не люди плохие |
| `AUDITOR_NO_LOGIN` | Аудитор не заходил 14 дней — аудита нет |
| `JOURNAL_GAP` | В журнале нет ни одной записи 2 часа в рабочее время — сервер не пишет |
| `CANARY_TOUCHED` | Кто-то открыл / изменил «приманку» (ниже) |

### Приманки (canary)

Фальшивые записи, которые никто не должен трогать:

- Ученик-призрак «Тест Тестов» в архивной группе. Любая отметка, оценка или пополнение ему = кто-то работает вслепую или ворует.
- Фальшивый «товар» в архиве магазина. Попытка выдать его = кто-то меняет заказы в обход интерфейса.
- Фальшивая строка с телефоном в базе. Если на номер пришёл спам — база утекла, и по номеру видно, когда.

## 11. Один урок поминутно (точки аудита)

Пример: группа Python, начало 15:00, кабинет 204.

| Время | Событие | Точка аудита |
|---|---|---|
| 14:40 | Админ открывает кабинет | чек-лист «кабинет готов» (свет, ПК, интернет) |
| 14:50 | Учитель приходит | `staff_checkins` с Wi-Fi школы; позже 14:55 = сигнал опоздания |
| 14:55 | Ученики заходят | ресепшн видит пришедших (если есть турникет / QR на входе) |
| 15:00 | Начало | код урока на проекторе |
| 15:00–15:10 | Отметка | время отметки, скорость, IP; родителю сообщение |
| 15:15 | Нет отметки | `ATT_LATE` уровень 0 (уже есть) |
| 15:10–16:20 | Урок | активность учеников на платформе; выборочный обход админа |
| 16:20 | Тема урока, ДЗ | `LESSON_NO_TOPIC`, `HW_NOT_GIVEN` |
| 16:25 | Коины за урок | выдачи, причины, кому |
| 16:30 | Конец | учитель отмечает уход |
| 16:30–16:40 | Сдача кабинета | чек-лист + фото; стулья, ПК, ноутбуки |
| 16:35 | Выборочная проверка | админ сравнивает с чек-листом |
| 20:00 | Вечер | бот спрашивает 1 ученика «как прошёл урок?» |
| 23:59 | Конец дня | сверка: списания = отметки, уроки = расписание |
| Утро | Отчёт | завучу: что не закрыто за вчера |

## 12. Отчёты из всего этого

- **Карточка учителя за месяц:** опоздания, отметки вовремя, скорость отметки, изменения задним числом, ДЗ, оценки,
  коины, кабинет, оценки учеников, сигналы, нарушения, причины. Одна страница.
- **Карточка ученика:** посещаемость по журналу и по подтверждению родителя, оценки, ДЗ, битвы, коины, покупки, жалобы.
- **Тепловая карта школы:** день недели × час, цветом — сигналы. Видно, что «пятница 18:00» — время нарушений.
- **Лента недели для CEO:** 10 самых странных событий недели, объяснённых одной строкой.
- **Сравнение филиалов** (если будет больше одного): одни и те же показатели рядом.

## 13. Как встроить

1. **Закрыть дыры** из раздела 0: `logAction` в wallet, shop, homework, ratings, battles, auth, telegram, orders.
2. **Поля для каждого действия:** в `details` писать `minutesFromStart`, `secondsForGroup`, `ip`, `device`, `onSchoolNetwork`.
   Список IP школы — в настройках (`school_networks`).
3. **Жёсткие запреты** — в контроллерах, рядом с текущими проверками прав. Ошибка с кодом и переводом на 3 языка.
4. **Сигналы** — новая таблица `signals (code, user_id, entity, entity_id, details, seen_by, seen_at, verdict)`.
   Не путать с `violations`: сигнал не штрафует и не эскалирует, его только смотрит аудитор и ставит «норм» / «нарушение».
   «Нарушение» создаёт запись в `violations` с правилом.
5. **Ночной прогон** сверок (раздел 9) — `cron` раз в сутки, по файлу на сверку в `server/rules/checks/`.
6. **Подтверждение родителем** — через существующий Telegram-бот, таблица `parent_confirmations`.
7. **Приманки** — скрипт `npm run seed-canaries`, флаг `is_canary` у записи, правило `CANARY_TOUCHED`.

### Порядок

| Этап | Что | Эффект |
|---|---|---|
| 1 | Закрыть дыры журнала | без этого остальное слепое |
| 2 | Запреты для посещаемости (раздел 1.2) | дешёвые, сразу убирают подделки |
| 3 | Таблица `signals` и страница аудитора «Сигналы» | аудитору есть что смотреть |
| 4 | Сигналы посещаемости и оценок | самые частые действия |
| 5 | Подтверждение родителем в Telegram | честная посещаемость |
| 6 | Ночные сверки, приманки, аудит аудита | ловит то, что не видно глазами |
| 7 | Карточки учителя и ученика, тепловая карта, лента CEO | решения на основе данных |
